# WPS 表格字段映射加载项交互设计

| 项目 | 内容 |
| --- | --- |
| 文档版本 | v2.0 |
| 日期 | 2026-10-21 |
| 产品形态 | WPS 表格加载项 |
| 核心载体 | 任务窗格、工作表第 1 行插件表头 |
| 核心流程 | 选模板 → 展示字段 → 拖动排序 → 上传导出 JSON |

## 1. 目标

用户选择一套预置模板后，加载项把模板中的字段按当前顺序写进工作表第 1 行的插件专用表头。用户在任务窗格中拖动字段调整列顺序，表头行随每次位置变化实时预览；确认后点击“上传”，把工作表数据按当前字段顺序导出为 JSON。

开发阶段只做这条主链路，不引入模板编辑、字段增删、多区域配置等能力。

## 2. 核心交互

```text
1. 选择模板
2. 任务窗格展示模板中的全部字段，并在工作表第 1 行创建插件专用表头行
3. 在任务窗格中拖动字段排序，表头行在每次位置更新时同步预览
4. 点击“上传”，按当前顺序读取表格内容并导出为 JSON
```

### 2.1 第 1 步：选择模板

- 任务窗格顶部只有模板下拉框，模板列表来自 `data/mock.json` 的 `templates`。
- 插件内不提供新建、复制、重命名、删除模板的入口。
- 首次进入时下拉框显示“请选择模板”；选择后记住该模板，下次打开任务窗格时恢复。
- 切换模板会重新解析该模板的字段树，并重写插件表头行。

### 2.2 第 2 步：展示全部字段并创建表头行

- 字段列表展示当前模板递归展开后的全部叶子字段，顺序即列顺序。
- 每个字段行显示：字段显示名、字段路径（如 `customer.contact.phone`）、所属分组、目标列字母。
- 源表第 1 行为原始表头。选择模板时检查工作表第 1 行：不存在插件表头则插入一行；已存在则复用，不重复插入。
- 插入后：第 1 行为插件表头，第 2 行为原始表头，第 3 行起为业务数据。
- 表头单元格使用字段显示名，并按列顺序写入 A、B、C……列。
- 切换字段更少的模板时，清空旧模板多出来的表头列。

### 2.3 第 3 步：拖动排序与实时预览

- 拖动字段行只改变字段与列的对应关系，不移动、不修改工作表中的业务数据。
- 每次目标位置发生变化时，立即按新顺序重写一次表头行，不等松手。
- 松手后提交新顺序，并按模板保存到本地。
- 拖拽取消（Esc、拖出列表后松手、任务窗格失焦）恢复拖动前的顺序和表头。
- 拖动期间禁用模板切换和上传，避免读取临时顺序。
- 表头写入串行执行，快速连续换位时以最后一次顺序为准。

排序示例：

```text
拖动前：A＝订单编号  B＝客户名称  C＝订单金额
拖动后：A＝订单金额  B＝订单编号  C＝客户名称
```

工作表的第 3 行起数据保持原位，只是被读取为不同的字段。

### 2.4 第 4 步：上传导出 JSON

- “上传”按钮按当前字段顺序读取工作表第 3 行至最后一行，跳过第 2 行原始表头。
- 每行按列位置依次对应一个叶子字段。
- 叶子字段的路径决定 JSON 嵌套层级，例如 `customer.contact.phone` 输出为：

```json
{ "customer": { "contact": { "phone": "13800000001" } } }
```

- 生成结果后立即在任务窗格中预览，并下载 `<工作表名>-<模板名>.json`。
- 支持复制完整 JSON、再次导出。

## 3. 模板数据

### 3.1 来源与边界

- 模板定义只来自 `data/mock.json`，是开发阶段唯一来源。
- 插件不写入、不修改模板定义。
- 插件本地只保存“当前模板 ID”和“每个模板下的字段顺序”，不复制模板字段。
- 模板字段被删除或新增后，保存的顺序会自动剔除失效字段、补齐新字段。

### 3.2 模板结构

```json
{
  "id": "tpl_order_standard",
  "name": "订单标准模板",
  "fields": [
    { "key": "orderNo", "label": "订单编号" },
    {
      "key": "customer",
      "label": "客户信息",
      "children": [
        { "key": "name", "label": "客户名称" },
        {
          "key": "contact",
          "label": "联系方式",
          "children": [
            { "key": "phone", "label": "联系电话" },
            { "key": "email", "label": "电子邮箱" }
          ]
        }
      ]
    },
    { "key": "orderDate", "label": "下单日期" },
    { "key": "amount", "label": "订单金额" },
    { "key": "status", "label": "订单状态" }
  ]
}
```

### 3.3 多层 JSON 解析规则

1. 从 `fields` 开始递归遍历，不限层级。
2. 带非空 `children` 的节点是分组，只参与路径和嵌套输出，不占列。
3. 没有子节点的节点是叶子字段，每个叶子字段占一列。
4. 叶子字段的唯一标识是完整路径，如 `customer.contact.phone`。
5. 叶子顺序默认按模板声明顺序深度优先展开。
6. 用户在任务窗格中的拖动顺序覆盖默认顺序。

## 4. 插件表头行

| 规则 | 说明 |
| --- | --- |
| 位置 | 固定为工作表第 1 行。 |
| 创建 | 首次选择模板时插入一行；已有插件表头时复用。 |
| 内容 | 按当前字段顺序写入叶子字段显示名。 |
| 样式 | 浅蓝填充、深蓝加粗文字，与业务数据区分。 |
| 数量变化 | 新模板字段更少时，清空旧模板多出的表头列。 |
| 原始表头 | 下移到第 2 行，保留用户原有列名，不参与导出。 |
| 数据位置 | 业务数据从第 3 行开始，导出时读取第 3 行至最后一行。 |

## 5. 导出 JSON

### 5.1 结构

```json
{
  "version": "2.0",
  "template": {
    "id": "tpl_order_standard",
    "name": "订单标准模板"
  },
  "sheet": "订单",
  "fields": [
    { "path": "orderNo", "label": "订单编号", "column": "A" },
    { "path": "customer.name", "label": "客户名称", "column": "B" },
    { "path": "customer.contact.phone", "label": "联系电话", "column": "C" }
  ],
  "records": [
    {
      "orderNo": "SO001",
      "customer": {
        "name": "张三",
        "contact": { "phone": "13800000001" }
      }
    }
  ]
}
```

### 5.2 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `version` | string | JSON 结构版本，当前为 `2.0`。 |
| `template.id` | string | 生成结果时使用的模板 ID。 |
| `template.name` | string | 生成结果时使用的模板名称。 |
| `sheet` | string | 读取时的工作表名称。 |
| `fields` | array | 本次导出使用的字段快照，按当前列顺序排列。 |
| `fields[].path` | string | 叶子字段的完整路径，用点号连接。 |
| `fields[].label` | string | 表头显示名。 |
| `fields[].column` | string | 对应的工作表列字母。 |
| `records` | array | 第 3 行起逐行读取的数据，不含原始表头。 |

### 5.3 取值规则

- 跳过第 2 行原始表头，只读取第 3 行起的数据。
- 每行只读取当前字段数量对应的前 N 列。
- 未映射列（超出模板字段数的列）不进入结果。
- 空单元格输出 `null`。
- 文本、数字、布尔值保持原类型。
- 日期输出 ISO 8601 字符串。
- 嵌套对象按字段路径合并，同一分组下的多个叶子字段落在同一个对象里。
- 工作表只有原始表头、没有数据行时，输出 `"records": []`。

## 6. 状态与异常

| 场景 | 处理 |
| --- | --- |
| 未选择模板 | 字段列表为空，上传按钮禁用，表头行不创建。 |
| 模板没有叶子字段 | 显示“模板中没有可用字段”，上传禁用。 |
| 第 1 行已有插件表头 | 复用该行，不重复插入。 |
| 源表没有原始表头 | 第 2 行会被当作原始表头跳过，需确保源表第 1 行是表头。 |
| 拖动中切换模板 | 模板下拉框禁用。 |
| 拖动中点击上传 | 上传按钮禁用。 |
| 拖拽取消 | 恢复拖动前顺序并重写表头。 |
| 表头写入失败 | 顶部显示错误摘要，保留当前字段顺序，可重新拖动或重新选择模板。 |
| 上传读取失败 | 不生成新结果，保留上一次结果并显示错误。 |
| 顺序改变后已有结果 | 结果保留，但标注“字段顺序已变化，请重新上传”。 |
| 工作表数据变化 | 已有结果标注为过期，用户重新上传后刷新。 |
| 切换模板 | 清空旧结果，字段列表和表头行切换到新模板。 |

## 7. 验收标准

- [ ] 模板下拉框只包含 mock 模板，且没有模板编辑入口。
- [ ] 选择模板后，任务窗格展示该模板递归展开后的全部叶子字段。
- [ ] 选择模板后，工作表第 1 行出现插件表头，原始表头下移到第 2 行，第 3 行起数据不变。
- [ ] 导出结果不包含原始表头行。
- [ ] 表头列顺序与字段列表顺序一致。
- [ ] 拖动字段时，每次目标位置变化都会更新一次表头行。
- [ ] 松手后顺序保存，重新打开任务窗格仍能恢复。
- [ ] 取消拖拽后顺序和表头恢复原状。
- [ ] 点击上传后生成按字段路径嵌套的 JSON，并下载文件。
- [ ] 多层字段（至少 3 层）的路径与嵌套输出正确。
- [ ] 空单元格输出 `null`，数字不变成字符串。
